# infra

## What it does
AWS CDK app (Python) that creates every AWS resource Burn uses, in `us-east-1`.
One stack per component, so each owner deploys their part without touching the rest.

## How it works
- `app.py` lists the stacks. Each stack lives in `burn_infra/<name>.py` and is owned by one lane.
- Stacks reference each other by fixed names (`contracts/python/burn_contracts/names.py`), not
  CloudFormation exports, so any stack can be redeployed alone.
- Lambda code is plain Python (stdlib + boto3). `burn_infra/assets.py` copies a handler folder plus the
  shared `burn_contracts` / `burn_detect` packages into `infra/.build/<name>/` at synth time. No Docker.
- System secrets (fingerprint HMAC key, demo token) are generated by Secrets Manager at deploy time.

## Key files
| File | Stack | Owner |
|---|---|---|
| `burn_infra/data.py` | BurnData: DynamoDB tables, system secrets | L0 / Lead |
| `burn_infra/identity.py` | BurnIdentity: Cognito badges | Identity + Gateway |
| `burn_infra/gateway.py` | BurnGateway: AgentCore Gateway, interceptors, tools | Identity + Gateway |
| `burn_infra/minter.py` | BurnMinter: minter, mock API provider | Credentials |
| `burn_infra/egress.py` | BurnEgress: proxy IAM identity | Detection |
| `burn_infra/burn_api.py` | BurnApi: Burn API | Lead |

## How to test it
```bash
cd infra
uv sync
npx aws-cdk@2 synth            # every stack synthesizes
npx aws-cdk@2 deploy BurnData  # deploy one stack (needs AWS credentials, us-east-1)
npx aws-cdk@2 deploy --all     # deploy everything
npx aws-cdk@2 destroy --all    # tear down
```
First time in a new account: `npx aws-cdk@2 bootstrap aws://<account-id>/us-east-1`.

Teardown note: Secrets Manager keeps deleted secrets for a recovery window, so redeploying right
after a destroy can fail on the secret names. Force-delete them first:
`aws secretsmanager delete-secret --secret-id burn-system/fingerprint-key --force-delete-without-recovery`
(same for `burn-system/demo-token`).

## If a judge asks...
- **Why so many stacks?** Six people (and, during the build, six agents) deploy in parallel.
  One stack per owner means nobody overwrites anyone else's deploy.
- **Where do the secrets come from?** AWS generates them at deploy time. No secret value is in the
  repo, in CDK code, or in a CloudFormation template.
- **Is anything wildcard?** No execution role gets wildcard actions. Each Lambda gets only the table
  and secret-name actions it needs.
